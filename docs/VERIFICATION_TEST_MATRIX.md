# Ready_Ai 검증 테스트 기준

이 문서는 다음 AI가 같은 기준으로 안정화 검증을 이어가기 위한 실행 목록이다. 확장 홈의 검증 센터는 `src/verification-suite.json`을 읽으므로, 검증 결과와 화면 표시는 이 파일을 단일 기준으로 맞춘다.

## 현재 기준

- 검증팩: V1.7.0
- 적용 앱: 2026-10-02.7
- 자동 검증: GPT 8개, Gemini 6개, AI Studio 5개를 플랫폼 전환 탭과 5개 카테고리로 분리하고 앱 `2026-10-02.7`에서 전체검증 5회 통과
- 무작위 상태 경로: 회당 125,000개
- 실웹 검증: GPT 9개, Gemini 6개, AI Studio 5개로 분리. GPT-WEB-01·07은 앱 `2026-08-19.6`에서 기준선 통과, 나머지는 각 서비스 대변동 시 실행

## 카테고리 기준

확장 홈에서는 먼저 GPT, Gemini, AIS 플랫폼 탭 중 하나를 고른다. 선택한 플랫폼의 자동·실웹 목록만 표시되고, 그 안에서 다음 카테고리가 접기·펼치기 목록으로 표시된다. 첫 카테고리만 기본으로 열려 있어 긴 목록도 빠르게 훑을 수 있다.

| 값 | 화면 이름 | 포함 범위 |
|---|---|---|
| `input` | 입력·단축키 | Enter, Ctrl/⌘+Enter, Shift+Enter, 한글 조합 |
| `generation` | 생성·편집 | 생성 감지, 이미지 편집, AI Studio Run |
| `queue` | 후속·대기열 | 후속 등록, 실행 순서, 자동 전송 |
| `recovery` | 복구·환경 | 숨김, 절전 복귀, 중복 인스턴스, 연속 안정성 |
| `ui` | UI·레이아웃 | 패널 위치, 화면 경계, 검증 데이터 표시 |

## 통과 버전 기록 규칙

- 통과한 항목은 `passedInAppVersion`에 실제로 검증한 앱 버전, `passedAt`에 검증 날짜를 기록한다.
- 자동 검증 항목을 다시 실행해 통과하면 마지막 통과 앱 버전으로 갱신한다.
- 실웹 `scheduled` 항목은 실행하지 않은 상태이므로 통과 버전을 만들지 않으며 화면에는 `통과 앱 버전 · 아직 없음`으로 표시한다.
- 화면의 `항목 Vx.x`는 테스트 정의 자체의 버전이고, `통과 앱 버전 · YYYY-MM-DD.N`은 그 테스트가 마지막으로 통과한 Ready_Ai 버전이다.

## 검증 주기 정책

모든 앱 버전에서 같은 강도의 테스트를 반복하지 않는다. 변경 위험도와 GPT 웹 변화 여부에 따라 아래 세 단계 중 하나만 적용한다.

| 단계 | 실행 조건 | 실행 범위 |
|---|---|---|
| 일상 변경 | 문구, 검증 데이터, 단순 UI 등 입력·전송 동작을 바꾸지 않는 변경 | 변경 범위 개별 테스트 + `--quick` 1회 |
| 핵심 로직 변경 | Enter, Ctrl/Cmd+Enter, 대기열, 이미지 편집 전송, 복구 로직 변경 | 관련 개별 테스트 + `--full` 전체 자동검증 5회 |
| 플랫폼 웹 대변동 | GPT·Gemini·AI Studio 입력창이나 전송 구조 변경, 서비스 업데이트 직후 오류 제보, 선택자 회귀 실패 | 해당 `--platform`의 `--full` 검증 5회 + 해당 플랫폼 실웹 검증 |

- 큰 변화가 없어도 90일마다 메시지를 보내지 않는 구조 점검만 수행한다.
- 구조 점검에서 변화가 감지된 경우에만 실웹 메시지 전송 검증으로 승격한다.
- `scheduled`는 실패나 미완료가 아니라 해당 플랫폼 웹 대변동 트리거를 기다리는 정상 상태다.
- 다음 구조 점검 기준일은 2026-11-17이다.

## 다음 AI 실행 순서

1. 변경 전 `src/verification-suite.json`과 이 문서를 읽는다.
2. 변경 대상이 GPT, Gemini, AI Studio 중 어디인지 먼저 선택한다.
3. 위 검증 주기 정책에 따라 일상 변경, 핵심 로직 변경, GPT 웹 대변동 중 한 단계를 선택한다.
4. 일상 변경은 `node tools/run-verification-suite.js --platform=<플랫폼> --quick`으로 1회 실행한다.
5. 핵심 로직 변경은 `node tools/run-verification-suite.js --platform=<플랫폼> --full`로 5회 반복한다.
6. 범위를 더 좁힐 때는 `--category=input|generation|queue|recovery|ui`를 함께 사용한다.
7. 플랫폼 웹 대변동일 때만 해당 플랫폼 자동검증 5회 후 해당 수동 시나리오를 실행한다.
8. 실패가 있으면 완료 상태나 완료 날짜를 갱신하지 않는다.
9. 검증 로직·범위가 바뀌면 해당 그룹 버전과 검증팩 버전을 올린다.
10. 앱 버전, 검증 완료 날짜, 반복 횟수, 상태를 JSON에 기록한 뒤 홈 표시와 일치하는지 확인한다.

## 플랫폼별 실웹 수동 시나리오

각 시나리오는 새 대화와 긴 대화에서 각각 확인한다. 중복 메시지, 입력 유실, 멈춘 입력창이 한 번이라도 나타나면 실패다.

### GPT · ChatGPT

1. `GPT-WEB-01` (입력·단축키) 일반 대화에서 Ctrl+Enter 직후 25/150/350/500/2000ms 간격의 Enter가 모두 후속 대기열로 들어가는지 확인한다.
2. `GPT-WEB-02` (후속·대기열) 답변 생성 중 Ctrl+Enter 조정과 다음 Enter 대기가 분리되는지 확인한다.
3. `GPT-WEB-03` (생성·편집) 이미지 편집 모달에서 편집 요청이 한 번만 전송되고 다음 Enter가 후속 대기하는지 확인한다.
4. `GPT-WEB-04` (생성·편집) 이미지 업로드 준비 중 전송 버튼 비활성·활성 전환과 중복 방지를 확인한다.
5. `GPT-WEB-05` (입력·단축키) Ready_Ai OFF에서 일반 Enter와 Ctrl+Enter 기본 동작이 보존되는지 확인한다.
6. `GPT-WEB-06` (입력·단축키) Shift+Enter, 한글 조합, 빠른 키 반복을 확인한다.
7. `GPT-WEB-07` (후속·대기열) 후속지시 3개가 응답 완료마다 한 항목씩 순서대로 자동 전송되는지 확인한다.
8. `GPT-WEB-08` (복구·환경) 숨김 탭·절전 복귀 후 큐와 순서가 보존되는지 확인한다.
9. `GPT-WEB-09` (복구·환경) 일반 대화와 이미지 편집을 섞어 10회 연속 실행한다.

## 완료 판정

- 자동 검증은 선택한 위험 단계의 지정 반복 횟수만큼 연속 통과해야 한다.
- 플랫폼 실웹은 해당 서비스의 대변동 검증을 시작한 경우에만 그 플랫폼의 모든 수동 시나리오를 통과해야 한다.
- 자동 검증과 실제 웹 검증을 구분해서 기록하며, 실행하지 않은 실제 웹 검증을 완료로 표시하지 않는다.
- 대변동이 아닌 버전에서는 실웹 항목을 `scheduled`로 유지하며, 이를 배포 실패로 판정하지 않는다.
- 검증 센터의 앱 버전과 팝업 상단 버전이 다르면 배포 완료로 판정하지 않는다.
